## Part 3: Automation rules that actually exist in code

Use this as the main decision matrix:

| Condition detected | Command generated | Meaning |
|---|---|---|
| `gasRaw > gasDangerThreshold` | `GAS_ALERT`, `BUZZER_ON`, `FAN_ON` | safety ventilation and alarm |
| `temperature < tempMin` | `BUZZER_ON` | cold warning |
| `temperature > tempMax` | `FAN_ON`, `BUZZER_ON` | heat response |
| `humidity < humidityMin` | `WATER_ON` | dry air response |
| `humidity > humidityMax` | `FAN_ON` | excess humidity ventilation |
| `soilRaw < soilDryThreshold` | `WATER_ON` | dry growing medium response |
| `lightRaw < darkThreshold` | `LIGHT_ON` | insufficient light response |
| pH outside range | `PH_WARNING` | nutrient solution warning |
| EC outside range | `FERT_ALERT` | fertilizer/nutrient warning |
| `co2Ppm < co2Min` | `CO2_LOW` | CO2 enrichment warning |
| `waterDistanceCm > waterLowCm` | `BUZZER_ON` | low tank level warning |
| `waterFlowLpm < waterFlowMin` | `WATER_ON` | insufficient flow response |

Important accuracy note:

Use `soilRaw < soilDryThreshold`, not `>`; the backend logic treats lower raw soil value as the dry-soil trigger.

## Part 4: Command lifecycle

Use this as a visual command card:

1. Backend creates a `deviceCommands` record.
2. Command status starts as pending.
3. ESP32 calls command endpoint.
4. Backend returns text command:

`COMMAND|INTERVAL_SECONDS|COMMAND_ID`

Example:

`WATER_ON|10|cmd_abc123`

5. ESP32 executes the command.
6. ESP32 reports command result.
7. Backend marks command as executed.

Poster copy:

The device is pull-based, which makes it simpler for real WiFi networks: the ESP32 asks the server for work, instead of requiring the server to maintain a live socket to every device.

## Part 5: Offline reliability

Use as a small "reliability" badge:

Offline queue:

- LittleFS stores readings during WiFi failure.
- Queue cap is 120 readings.
- Device can flush queued readings after reconnecting.

Poster copy:

The farm can survive short network gaps without losing the automation story.

## Part 6: Manual override and safety

Use this text:

SeedDown supports both automatic and manual commands:

- Automatic: generated by sensor rules.
- Manual: triggered from the Control Page.
- Emergency: `NO_ACTION` can clear or stop active intervention.

Supported command set:

`NO_ACTION`, `WATER_ON`, `LIGHT_ON`, `FAN_ON`, `BUZZER_ON`, `PH_WARNING`, `FERT_ALERT`, `CO2_LOW`, `GAS_ALERT`
